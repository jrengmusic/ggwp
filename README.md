# GGWP
**GlyphSheet Generation Workflow Protocol**

A native command-line tool that turns SVG glyph sheets into TrueType fonts. Draw your glyphs in any graphics editor. GGWP builds the font.

---

## Why

Making a font is a tedious process. It is gatekept by type designers, by their domain-specific specs, and by obnoxious, expensive apps that are the only way to produce one.

Those WYSIWYG apps are made by type designers, for type designers. A closed ecosystem from the start — even an experienced graphic designer hits a wall trying to pick up the domain skill. The apps are crowded with tools, metrics, and jargon. All of it is friction. All of it kills the fun of making your own typeface.

SVG, on the other hand, is easy to create — authored by hand, or generated by a program. Designing the glyphs is the fun part, and the easiest part. Any graphics editor can do it. Out of the box, a common graphics editor is miles ahead in intuition for designing anything, typeface glyphs included.

GGWP removes the friction from typeface making. The designer focuses on the fun part: designing glyphs in the graphics editor of their choice. GGWP handles the rest, and produces a deterministic, ready-to-use TrueType font.

---

## Architecture

Set and forget. The manifest holds the metrics, the names, and the glyph set. Write it once, then leave it alone.

Deterministic command line. The manifest, the glyph sheet, and the binary decide the output bytes. No timestamps, no paths, no host state. Run it twice, get the same file.

Init. Design with whatever software you please. Export with one simple command.

## What

### Command Line

| Command | What it does |
| --- | --- |
| `ggwp --init=<font-name>` | creates whatever is missing, then reconciles the glyph sheets against the manifest's glyph table |
| `ggwp --build=<manifest.md> --weight=<table> --out=<font.ttf>` | reads the manifest and the weight's glyph sheet, writes the font, then validates it |
| `ggwp --extract=<font.ttf> --manifest=<manifest.md> --weight=<table>` | reads an existing font, then writes that weight's glyph sheet |
| `ggwp --version` | prints the version number |
| `ggwp --help` | prints the full guide |

Each long option takes its value after an equals sign. `--weight` names a weight table in the manifest.

```bash
ggwp --init="My Font"
ggwp --build=my-font.md --weight=regular --out=MyFont-Regular.ttf
```

`ggwp --help` is the complete reference: every contract, every manifest table, every key.

### Manifest

The manifest is a markdown file of grid tables. One manifest declares every weight.

- `## metrics` — ascender, descender, line gap, cap height, x-height, and the sheet's cell geometry
- `## font` — copyright, family, trademark, manufacturer, designer, description, URL, version
- `## glyphs` — one row per glyph. The single source of truth for which glyphs exist
- `## guides` — the reference lines drawn on the sheet
- `## colour` — every colour of the sheet
- one table per weight — the glyph sheet path, style, full name, PostScript name, weight class, and optional per-weight vertical metrics

The units per em is 1024 for every font. It is a contract constant, not a manifest value.

### Init

`--init` derives the manifest name from the family name: `My Font` gives `my-font.md`. With no manifest and no sheet, it writes both. With a manifest and a sheet, the `## glyphs` table drives the sheet: a new row gains a cell, a removed row loses its cell and its artwork, and the remaining cells repack. Your artwork moves with its cell. Your own top-level elements survive. One pass covers every weight. A second run over the same inputs gives the same files.

### Glyph Sheet

One SVG per weight. Each glyph is a group with an id of an underscore and a four-digit hexadecimal codepoint. More codepoints in one id make a ligature.

```
_0041         the letter A
_2122         the trade mark sign
_0066_0069    the f-i ligature
```

The group's first rectangle is the cell. Its position places the artwork. Its width sets the advance width. A guides layer draws the label, the reference lines, and the cell guides of each cell. GGWP ignores that layer when it reads the sheet back.

### Build

`--build` writes an sfnt file with TrueType outlines: `head`, `hhea`, `maxp`, `hmtx`, `post`, `cmap` (format 4, plus format 12 above U+FFFF), `name` (Macintosh and Windows records), `OS/2`, `glyf`, `loca`, and `GSUB` when the sheet holds a ligature.

Cubic curves become quadratic curves within one font unit. The fixed-pitch flag derives from the glyph advances.

GGWP then loads the font back through FreeType and checks the glyph count, the character map, every advance width, and every outline against the manifest. A failed check is fatal. Every failure exits non-zero.

### Extract

`--extract` runs the chain in reverse. It reads a TrueType font, scales it to 1024 units per em, and writes a glyph sheet. It finds ligatures by shaping. A build of the extracted sheet gives the same advances back.

## How

**Requirements:** C++17 compiler, CMake 3.25+, Ninja, JUCE 8.0.14 (exact match) at `../../JUCE`, JAM at `../jam`

```bash
# Release, unsigned
cmake -S . -B Builds/Release -G Ninja -DCMAKE_BUILD_TYPE=Release -DCAST_SIGN=OFF
ninja -C Builds/Release

# Debug
cmake -S . -B Builds/Debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
ninja -C Builds/Debug
```

`CMakeLists.txt` is generated by `cast` from `project-info.md`. Edit `project-info.md` and `cast/`, never `CMakeLists.txt`.

Every build copies the binary to `~/.local/bin/ggwp`.

GGWP has no config file. The manifest is the config. `ggwp --init` writes a default manifest into the current directory.

Platform notes:

- **macOS** — universal binary (`x86_64` and `arm64`), deployment target 11.0. A Release build with `CAST_SIGN=ON` signs, packages, notarizes, and staples a `.pkg`. It needs the Developer ID certificates and the `notary` keychain profile.
- **Windows** — a Release build with `CAST_SIGN=ON` builds a signed installer with NSIS and `signtool`.

The signed macOS `.pkg` is on [Releases](https://github.com/jrengmusic/ggwp/releases). It installs `ggwp` on your PATH.
